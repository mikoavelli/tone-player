# TonePlayer

Десктопное приложение для воспроизведения контрольных частот на акустической
системе. Последовательно проигрывает частоты из настроек, показывает текущую
частоту и оставшееся время. Окно — эквалайзер: у каждой частоты свой вертикальный
ползунок, поэтому характеристику системы можно править на слух или по прибору.

## Возможности

- Python 3.14.8, uv, PyQt6, потоковый вывод через sounddevice (PortAudio).
- Без numpy: синус берётся из таблицы, буфер заполняется через RawOutputStream.
- Все настройки лежат в одном файле `settings.json` рядом с программой: частоты
  полос, поправка уровня каждой полосы, диапазон и шаг ползунков, время тона,
  частота дискретизации, затухание, опорный и общий уровень, устройство вывода,
  пресеты и автовоспроизведение. Значений по умолчанию нет: без файла программа
  не запускается.
- Вертикальные ползунки полос: по умолчанию от −10 до +10 дБ с шагом 0,5 дБ;
  диапазон и шаг меняются в настройках.
- Ползунок мастера ходит на тот же диапазон вокруг опорного уровня и показывает
  итоговый уровень в дБ от полной шкалы.
- Настройки открываются шестерёнкой: шкала ползунков, опорный уровень, время
  тона, затухание, частота дискретизации, перестройка сетки частот и сброс
  уровней.
- Пресеты: выпадающий список в шапке, сохранение и удаление. Пресет хранит
  полосы и устройство вывода.
- У каждой полосы своя кнопка прослушивания; текущая полоса подсвечивается и
  сама прокручивается в видимую область.
- Переключение частот вручную кнопками «◀» и «▶» и переключатель
  автовоспроизведения (его состояние запоминается).
- Выбор устройства вывода списком в шапке с автоматическим подбором числа каналов.
- Счётчик оставшегося времени и прогресс текущего тона.
- Потоковый вывод: ползунки уровня применяются мгновенно, без щелчков на
  границах тонов (плавные нарастание и затухание).

Состояние разработки: эквалайзер, настройки, пресеты и воспроизведение готовы.
Ядро выравнивания по показаниям звукомера осталось в `src/equalizer.py` и покрыто
тестами, но в окне ввода показаний нет: уровни выставляются ползунками.


## Структура проекта

```
settings.json          все настройки программы (лежит рядом с exe)
src/main.py            точка входа
src/settings_store.py  чтение, проверка, миграция и запись settings.json
src/models.py          настройки, шкала ползунков, полосы, пресеты
src/presets.py         операции с пресетами (сохранить, применить, переименовать)
src/equalizer.py       набор полос и выравнивание по показаниям звукомера
src/audio_engine.py    генерация тонов и работа с устройством вывода
src/main_window.py     окно эквалайзера
src/band_widgets.py    ползунки, шкала и колонки полос
src/settings_dialog.py диалог настроек
src/ui_signals.py      протоколы сигналов Qt
src/ui_text.py         форматирование чисел
src/theme.py           цвета оформления
stubs/                 заглушки типов для sounddevice (только для basedpyright)
tests/                 модульные тесты
TonePlayer.spec        сборка PyInstaller
```

## Установка uv

Проект запускается и собирается через [uv](https://docs.astral.sh/uv/).

### Windows

Через PowerShell:

```powershell
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
```

Или через WinGet:

```powershell
winget install --id=astral-sh.uv -e
```

### Linux и macOS

```sh
curl -LsSf https://astral.sh/uv/install.sh | sh
```

Проверка установки:

```sh
uv --version
```

## Запуск

Из корня проекта:

```sh
uv sync
uv run python src/main.py
```

## Настройки

Файл `settings.json` лежит рядом с программой и обязателен: значений по умолчанию
нет, поэтому без него (или с повреждённым файлом) программа не запускается.
Формат рассчитан на машинную запись; править файл вручную не требуется.

```json
{
  "schema_version": 2,
  "playback": {
    "seconds_per_tone": 10.0,
    "sample_rate": 48000,
    "fade_ms": 20.0,
    "autoplay": true
  },
  "output": {
    "device": null,
    "reference_level_db": -12.0,
    "master_level_db": -12.0
  },
  "levels": {"min_db": -10.0, "max_db": 10.0, "step_db": 0.5},
  "bands": [
    {"frequency_hz": 500.0, "level_db": 0.0},
    {"frequency_hz": 1000.0, "level_db": 0.0}
  ],
  "presets": [
    {"name": "Колонки", "device": null, "bands": [{"frequency_hz": 500.0, "level_db": -1.5}]}
  ],
  "active_preset": "Колонки"
}
```

Правила проверки (любое нарушение считается повреждением файла):

- все параметры обязательны, неизвестные ключи не допускаются;
- частоты полос идут строго по возрастанию, не ниже 20 Гц и строго ниже половины
  `sample_rate` (частоты Найквиста), иначе тон отразится в более низкую частоту
  (алиасинг); полос от 1 до 64;
- диапазон ползунков `levels`: нижняя граница от −30 до 0 дБ, верхняя — от 0 до
  +30 дБ, шаг — от 0,1 до 5 дБ; ширина диапазона и нижняя граница должны делиться
  на шаг, а шаг — делить 60 дБ диапазона мастера, чтобы все положения ползунков
  попадали на его сетку;
- поправка полосы `level_db` лежит в диапазоне `levels` и кратна его шагу;
- общий уровень `master_level_db` — от −60 до 0 дБ относительно полной шкалы, кратен
  шагу ползунков;
- `reference_level_db` — опорный уровень мастера, от −60 до 0 дБ и кратен шагу;
  ползунок мастера ходит на диапазон `levels` вокруг него;
- `autoplay` — `true` или `false`;
- `seconds_per_tone` — от 1 до 3600 с, `sample_rate` — от 8000 до 768000 Гц,
  `fade_ms` — от 1 до 1000 мс;
- `device` — `null` (системное устройство вывода) или метка вида «название [звуковой
  интерфейс]»; индексы PortAudio между запусками нестабильны и не хранятся;
- имя пресета: непустое, до 64 символов, без пробелов по краям, уникальное без
  учёта регистра; `active_preset` — имя существующего пресета или `null`.

Файл первой версии (`schema_version: 1`) читается автоматически: ползунки получают
диапазон ±10 дБ с шагом 0,5 дБ, опорным уровнем мастера становится текущий общий
уровень, автовоспроизведение — включено. При первом изменении файл перезаписывается
в версии 2. Файл с неизвестной версией схемы не изменяется.


Запись атомарная (временный файл рядом и замена), перед записью данные проверяются.
Если файл недоступен для записи (например, программа лежит в защищённой папке),
причина показывается внизу окна, а запись повторяется при следующем изменении.

Повреждённый файл при запуске переименовывается в
`settings.corrupted-<дата>-<время>.json` и не затирается; после исправления ему
возвращают имя `settings.json`. Файл с неизвестной версией схемы
(`schema_version`) не изменяется.

### Эквалайзер и настройки

Полосы показаны вертикальными ползунками в прокручиваемой ленте: видно столько
колонок, сколько помещается, остальные доступны колесом мыши или полосой
прокрутки. Текущая полоса подсвечивается и автоматически подкручивается в
видимую область. Уровень полосы виден у активной колонки и при наведении;
двойной щелчок или правая кнопка мыши сбрасывают полосу в 0 дБ.

Диапазон и шаг всех ползунков задаются в настройках (по умолчанию ±10 дБ с шагом
0,5 дБ). Там же меняются опорный уровень мастера, время тона, затухание, частота
дискретизации и сетка частот; кнопка «Сбросить уровни» обнуляет все поправки, а
«Перестроить сетку» заменяет полосы равномерной сеткой. Применение настроек
останавливает воспроизведение: набор частот и шкала могли измениться.

### Пресеты

Пресет — именованный набор полос (частоты и поправки уровня) и устройство вывода,
на котором он подобран. В шапке окна пресет выбирается списком, сохраняется
кнопкой со стрелкой вниз и удаляется корзиной. Применение пресета заменяет полосы
и устройство, но не трогает общий уровень и автовоспроизведение, чтобы громкость
не менялась неожиданно. Если устройства из пресета нет на этом компьютере,
выбирается устройство по умолчанию и об этом сообщается. Все пресеты хранятся в
том же `settings.json`.

### Устройство вывода

По умолчанию (`device: null`) звук идёт в системное устройство вывода — это
правильный выбор для PipeWire/PulseAudio и Windows. Конкретное устройство
выбирается списком в шапке окна (список строится из устройств PortAudio) и
запоминается в файле по метке. Во время воспроизведения список заблокирован. Если
запомненного устройства нет, выбирается устройство по умолчанию, а метка в файле
остаётся прежней. Если выбранное устройство не открывается, приложение пробует
стерео вместо моно, затем системное устройство по умолчанию и показывает причину
в строке состояния внизу окна.

### Уровень сигнала

Ползунок мастера двигается на диапазон ползунков (по умолчанию ±10 дБ) вокруг
опорного уровня и показывает итоговый уровень в дБ от полной шкалы. Итоговый
уровень тона равен уровню мастера плюс поправка полосы; значения выше 0 дБ
ограничиваются полной шкалой, чтобы не было перегрузки. Поэтому при выравнивании
по измерениям опорной становится самая «тихая» частота: поднять сигнал выше
полной шкалы нельзя, остальные частоты опускаются до её давления.

### Управление воспроизведением

Главная кнопка меняется по состоянию: «Старт» запускает воспроизведение с
выбранной частоты (после завершения сеанса — заново с первой), «Пауза»
приостанавливает звук с сохранением позиции, «Продолжить» возобновляет его.
Кнопка «Стоп» прекращает воспроизведение, возвращает позицию к первой частоте и
освобождает устройство вывода.

Кнопка с треугольником под полосой прослушивает именно эту частоту: запускает
её с начала, а у звучащей полосы работает как пауза/продолжение. Полоса,
которая звучит сейчас, подсвечена акцентной рамкой.

### Переключение частот

Кнопки «◀» и «▶» рядом с частотой и щелчок по полосе выбирают тон, не выходя за
границы списка. Переключатель «Автовоспроизведение» в шапке показывает своё
состояние и задаёт, что происходит при переключении:

- «включено» (по умолчанию) — во время воспроизведения новая частота звучит
  сразу;
- «выключено» — частота меняется без звука, запуск выполняется кнопкой «Старт».

Если воспроизведение не идёт (до запуска, на паузе, после завершения сеанса),
переключение только выбирает частоту и звук не включает, независимо от
автовоспроизведения: запуск — кнопкой «Старт», продолжение после паузы —
кнопкой «Продолжить».

Кнопка «Старт» воспроизводит с выбранной частоты, а после завершения сеанса —
заново с первой.


## Тестирование и проверки

```sh
uv run python -m unittest discover -s tests
uv run ruff check .
uv run basedpyright
```

Отдельный модуль:

```sh
uv run python -m unittest tests/test_settings_store.py
uv run python -m unittest tests/test_presets.py
uv run python -m unittest tests/test_equalizer.py
uv run python -m unittest tests/test_audio_engine.py
```

Тесты не требуют звуковой карты: воспроизведение проверяется через подменённый
поток вывода.

## Сборка

PyInstaller собирает приложение для платформы, на которой запускается сборка.
Сборка Windows-версии выполняется на Windows.

```sh
uv sync --group build
uv run pyinstaller --clean TonePlayer.spec
```

Результат сборки находится в `dist/`. Файл `settings.json` копируется в `dist/`
вручную и должен лежать рядом с `TonePlayer.exe`. В сборку попадают
`portaudio.dll` и `_sounddevice.pyd` — дополнительных установленных программ
не требуется.
