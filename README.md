# TonePlayer

Десктопное приложение для воспроизведения контрольных частот на акустической
системе. Последовательно проигрывает 20 частот из конфигурации, показывает
текущую частоту, оставшееся время и уровень сигнала.

## Возможности

- Python 3.14.8, uv, PyQt6, потоковый вывод через sounddevice (PortAudio).
- Без numpy: синус берётся из таблицы, буфер заполняется через RawOutputStream.
- Конфигурация в TOML: список частот, время каждого тона, целевое давление.
- Калибровочный коэффициент уровня для каждой частоты (`gain_db_i`).
- Калибровка прямо в окне: вводится показание звукомера, приложение пересчитывает
  `gain_db_i` тона и записывает его в `config.toml`.
- Кнопки «Старт», «Пауза»/«Продолжить», «Стоп», ползунок уровня от −12 до
  +12 дБ с шагом 0,5 дБ.
- Переключение частот вручную кнопками «◀» и «▶» и переключатель
  автовоспроизведения.
- Выбор устройства вывода списком в окне с автоматическим подбором числа каналов.
- Счётчик оставшегося времени и индикаторы прогресса тона и сеанса.
- Потоковый вывод: ползунок уровня применяется мгновенно, без щелчков на
  границах тонов (плавные нарастание и затухание).

## Структура проекта

```
config.toml          настройки: частоты, время, калибровка уровня
src/main.py          точка входа
src/config_loader.py чтение и проверка конфигурации, запись gain_db_i
src/calibration.py   пересчёт калибровки по показанию звукомера
src/models.py        модели конфигурации и прогресса
src/audio_engine.py  генерация тонов и работа с устройством вывода
src/main_window.py   окно приложения
stubs/               заглушки типов для sounddevice (только для basedpyright)
tests/               модульные тесты
TonePlayer.spec      сборка PyInstaller
```

## Установка uv

Проект запускается и собирается через [uv](https://docs.astral.sh/uv/).

### Windows

Через PowerShell:

```powershell
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
```

Или через WinGet:

```powershell
winget install --id=astral-sh.uv -e
```

### Linux и macOS

```sh
curl -LsSf https://astral.sh/uv/install.sh | sh
```

Проверка установки:

```sh
uv --version
```

## Запуск

Из корня проекта:

```sh
uv sync
uv run python src/main.py
```

## Конфигурация

Файл `config.toml` используется как внешний и должен находиться рядом с
приложением.

```toml
[playback]
number_of_constants = 20
f_i = [500, 1000, ... , 10000]   # частоты, Гц (строго ниже sample_rate / 2)
seconds_per_tone = 10.0         # время одной частоты, с
target_spl_db = 90.0            # целевое звуковое давление, дБ

[calibration]
gain_db_i = [-12.0, ... ]       # ослабление каждой частоты, дБ

[output]
sample_rate = 48000
fade_ms = 20.0
device = "default"             # устройство вывода: индекс, имя или "default"
default_offset_db = 0.0         # стартовое положение ползунка
```

Каждая частота `f_i` должна быть строго ниже половины `sample_rate` (частоты
Найквиста): при 48 кГц это 24 кГц. Иначе тон отразится в более низкую частоту
(алиасинг) и прозвучит не тот сигнал, что указан в конфигурации. Загрузчик
отклоняет такую конфигурацию с понятной ошибкой. Для более высоких частот
увеличьте `sample_rate`.

### Устройство вывода

По умолчанию звук идёт в системное устройство вывода (`default`) — это
правильный выбор для PipeWire/PulseAudio и Windows, потому что индексы PortAudio
нестабильны между запусками.

Конкретное устройство выбирается списком «Устройство вывода» в окне (список
строится из устройств PortAudio). Если выбранное устройство не открывается,
приложение пробует стерео вместо моно, затем системное устройство по умолчанию
и показывает причину в строке состояния под списком.

### Калибровка уровня

`gain_db_i` — ослабление каждой частоты относительно полной шкалы цифрового
сигнала (0 дБ = 1.0). Значения подбираются звукомером: усиление колонок
подбирается так, чтобы измеренное давление на каждой частоте соответствовало
`target_spl_db`. Пока прибора нет, оставьте одинаковое значение (например
−12 дБ) и пользуйтесь ползунком.

#### Калибровка в окне

Карточка «Калибровка» относится к тону, частота которого указана в её заголовке:

1. Включите тон и измерьте звуковое давление звукомером.
2. Введите показание в поле «Измерено звукомером» (Enter или переход в другое поле
   фиксирует значение) и нажмите «Применить».
3. Приложение сдвигает `gain_db_i` тона на разность `target_spl_db − измерено`,
   округляет до 0,1 дБ, применяет сразу (звучащий тон меняется на лету) и записывает
   в `config.toml`.

Заметьте: измерение считается сделанным при текущем положении ползунка уровня.
Ползунок остаётся временной поправкой поверх калибровки, поэтому после «Применить»
общая громкость при том же положении ползунка меняется ровно на разность «цель −
измерено». Если после поправки давления всё равно не хватает, даже когда сигнал
на полной шкале (0 дБ), значение ограничивается нулём, а приложение подсказывает, на
сколько дБ поднять усиление колонок. Диапазон `gain_db_i` — от −96 до 0 дБ.

Для каждого тона введённое, но не применённое показание запоминается, пока окно
открыто. При автовоспроизведении тон меняется сам, поэтому для калибровки удобнее
выключить автовоспроизведение или поставить воспроизведение на паузу.

В файле заменяется только список `gain_db_i` в секции `[calibration]`: комментарии,
порядок и остальные значения остаются как были. Результат перед записью
проверяется, запись атомарная (временный файл и замена). Если файл недоступен для
записи (например, программа лежит в защищённой папке), значение остаётся
применённым в окне, а причина показывается под полем; следующее «Применить»
запишет все накопленные изменения.

Итоговый уровень тона в дБ равен `gain_db_i[номер] + положение ползунка`.
Значения выше 0 дБ ограничиваются полной шкалой, чтобы не было перегрузки.
Ползунок меняет уровень в пределах ±12 дБ с шагом 0,5 дБ; значение
`default_offset_db` из конфигурации задаёт его стартовое положение и
ограничивается этими границами.

### Управление воспроизведением

Главная кнопка меняется по состоянию: «Старт» запускает воспроизведение с
выбранной частоты (после завершения сеанса — заново с первой), «Пауза»
приостанавливает звук с сохранением позиции, «Продолжить» возобновляет его.
Кнопка «Стоп» прекращает воспроизведение, возвращает позицию к первой частоте и
освобождает устройство вывода.

### Переключение частот

Кнопки «◀» и «▶» рядом с частотой переключают тон вручную, не выходя за
границы списка. Кнопка-переключатель «Автовоспроизведение» показывает своё
состояние и задаёт, что происходит при переключении:

- «включено» (по умолчанию) — во время воспроизведения новая частота звучит
  сразу;
- «выключено» — частота меняется без звука, запуск выполняется кнопкой «Старт».

Если воспроизведение не идёт (до запуска, на паузе, после завершения сеанса),
переключение только выбирает частоту и звук не включает, независимо от
автовоспроизведения: запуск — кнопкой «Старт», продолжение после паузы —
кнопкой «Продолжить».

Кнопка «Старт» воспроизводит с выбранной частоты, а после завершения сеанса —
заново с первой.

## Тестирование и проверки

```sh
uv run python -m unittest discover -s tests
uv run ruff check .
uv run basedpyright
```

Отдельный модуль:

```sh
uv run python -m unittest tests/test_config_loader.py
uv run python -m unittest tests/test_audio_engine.py
uv run python -m unittest tests/test_calibration.py
uv run python -m unittest tests/test_ui.py
```

Тесты не требуют звуковой карты: воспроизведение проверяется через подменённый
поток вывода.

## Сборка

PyInstaller собирает приложение для платформы, на которой запускается сборка.
Сборка Windows-версии выполняется на Windows.

```sh
uv sync --group build
uv run pyinstaller --clean TonePlayer.spec
```

Результат сборки находится в `dist/`. Файл `config.toml` копируется в `dist/`
вручную и должен лежать рядом с `TonePlayer.exe`. В сборку попадают
`portaudio.dll` и `_sounddevice.pyd` — дополнительных установленных программ
не требуется.
